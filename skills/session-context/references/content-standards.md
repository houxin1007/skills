# 内容标准

## 值得记录的判断标准
满足以下任一条件就应该记录：

| 条件 | 示例 |
|---|---|
| 涉及架构/方向决策 | 选型理由、技术方案变更 |
| 用户明确表达偏好 | "图片用本地不用远程"、"端口不用3000" |
| 踩坑后找到解决方案 | 编码问题、环境配置、兼容性 |
| 多步骤任务的中间状态 | 已完成A和B，C待做 |
| 项目约定/规范 | 命名规则、目录结构约定 |
| 用户表达的未来计划 | "后续要做斗技出场率算法" |

## 不应该记录的
- 单行代码修改
- 标准库用法
- 一般性问答
- 用户没有明确方向的随意讨论

## 内容原则
- **面向未来**：写的是"下次会话要知道什么"，不是"这次做了什么"
- **精简优先**：5 行比 20 行好，20 行比 200 行好
- **方向感**：让读者知道项目往哪里走
- **避免重复**：已有信息不要重复记录
